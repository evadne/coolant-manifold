# Temporary files and local work

`tmp/` is an ignored local scratch directory. Its former undocumented presence was a reproducibility trap: some preview and legacy render operations read intermediate meshes from it. A fresh Git clone does not contain those files. It is not the canonical output location and must not be uploaded to JLC.

| Local contents | Purpose | Recovery / retention |
|---|---|---|
| `mesh-long-bore-Q/` and related mesh folders | Intermediate display meshes, including coloured gallery volumes | Q gallery meshes can be regenerated from retained fluid-volume STEP files using the command below. Older versions use their matching builders. |
| `scene*.json` | Historical renderer inputs | Generated by the corresponding historical builder; do not use them to select current geometry. |
| Preview PNGs and render/build logs | Iteration and diagnosis | Usually disposable after needed evidence is retained in `output/`; inspect before deletion. |
| Downloaded pages, PDFs, ZIPs and extracted vendor assets | Research and conversion cache | Preserve any irreplaceable provenance in `docs/references/` before cleanup; not every local download is reproducible automatically. |
| `radiator-fea/` and solver intermediates | Meshes and solver working files | Follow the relevant analysis scripts. Retained analysis evidence lives under versioned `output/` directories. |
| One-off scripts and inspection notes | Local experiments | Not part of the supported build path. Promote needed logic into `scripts/` before relying on it. |

The tracked `tmp/README.md` is the sole intentional exception to the ignore rule. All other scratch files stay local. Do not delete the whole directory while CAD/Blender/solver jobs are running, and do not assume every one-off experiment is regenerable.

## Q diagnostic mesh preparation

The current Q inspection renderer loads its finished body and plate from `output/manufacturing/`, but its translucent diagnostic view also needs two gallery meshes. Create these without regenerating historical CAD or changing submitted outputs:

```sh
.venv/bin/python - <<'PYTHON'
from pathlib import Path
import cadquery as cq
cache = Path('tmp/mesh-long-bore-Q')
cache.mkdir(parents=True, exist_ok=True)
for i in (1, 2):
    solid = cq.importers.importStep(f'output/long-bore-Q/cad/fluid-network-{i}.step')
    cq.exporters.export(solid, str(cache / f'fluid-network-{i}.stl'))
PYTHON
```

The renderer also uses the retained P scene as a lighting/reference base. Historical outputs can therefore be active build dependencies even when they are not current fabrication choices. See [rebuild instructions](rebuild.md) and [output roles](../output/README.md).
